# 第七码

第三款网页悬疑恐怖解谜游戏的独立项目。

玩家扮演音频修复师陈默，在父亲去世后打开一套废弃的音轨修复系统。修复开始后，系统显示还有一名未知监听者正在同步改写工程。七次修复针对同一段 86 秒事故原轨，逐层验证十四年前录音棚火灾的声源、方位、先后、说话人、素材来源、警报状态和删改流程。

乔岚与童年陈默约定：前六次由她发出，停顿后由另一个人回应一次。事故当晚，她在被锁住的门后再次发出六次呼叫，而陈默在走廊作出了第七次回应。游戏不要求辨认音高，只要求玩家根据页面给出的规则与中立证据完成推导。

## 当前阶段

- 已完成强化悬疑恐怖后的核心剧本、角色关系、双时间线威胁、谜题链与多结局设计。
- 已完成第一版可玩网页：七章音轨谜题、终章事实链、三种结局、三层提示、本地存档与全文字辅助均可操作。
- 七章默认采用逐步修复模式：先用通俗语言说明本章要证明什么，再按顺序开放试听、比较、选择和提交；当前下一步会持续高亮。
- 试听与处理会生成“自动观察记录”：只保存事件来源、到达时差、动作时间、信号入口、测量参数和持续状态，不直接填写答案。
- 每章使用一条决定性主线索和一条可选佐证；难度来自解释、匹配与组合证据，不来自不可辨认的声音。
- 人物对白已改为随游戏发布的 37 段固定中文语音素材，不再调用玩家设备的浏览器朗读；谜题旋律、房间响应、敲击样本和相位状态仍由 Web Audio 生成。
- 播放器会在每次试听前确认浏览器音频已真正启动；固定人声解码后与谜题声音进入同一 Web Audio 会话。第一章三条旋律已单独校准响度，播放被浏览器阻止时会明确提示重试。
- 所有声音共用单一播放会话：新试听、章节切换、关闭声音和离开结局页都会停止上一段；顶部播放器只重播最后点击的样本，样本名称、编号、波形、字幕与实际声音保持一致；章节完成后不再自动插播监听者对白。
- 第六章用“继电器消失而音乐、人声继续”排除断电与话筒故障；第七章将七条历史删改规则与当前操作进行语义配对。
- 已配置 GitHub Pages 自动发布；推送到 `main` 后会生成公开试玩版本。

## 技术栈

- Vinext、Next.js、React、TypeScript、CSS。
- Canvas 绘制波形，Web Audio API 生成非人声证据样本。
- 固定 MP3 人声素材提供稳定角色声线与响度，浏览器不再运行 Web Speech API。
- pnpm 管理依赖。
- `localStorage` 保存设备本地进度。

## 常用命令

```bash
pnpm install
pnpm run dev
pnpm run build
pnpm test
pnpm run lint
```

维护人声素材时，可安装 `edge-tts` 与 `ffmpeg`，再运行
`python3 scripts/generate_voice_assets.py`。该脚本只用于制作期，玩家运行游戏时不需要联网生成语音。

## 核心规则

- 游戏始终发生在同一台音轨修复工作台内。
- 线索来自声源编号、话筒到达时差、动作因果、物理通道、音频测量、同步信号和剪辑痕迹。
- 悬疑由旧案真相、玩家缺失的七分钟记忆和当前第二监听者三条线同时推进。
- 不要求玩家具备乐理、绝对音感或音频工程知识。
- 所有听觉线索都提供可视化与文字辅助。
- 专业音频术语会在首次出现时解释，提示位于当前任务旁，不需要在侧栏中寻找。
- 叙事对白、谜题比较音与环境层分时播放；新的试听会立即停止上一段，避免声音叠加。
- 不靠持续噪声或高音量惊吓，恐怖来自一段被反复改写的事故录音、门内外的 6+1 回应和正在等待玩家完成第七次删除的远端光标。
